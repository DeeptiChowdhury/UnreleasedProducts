# Building the Tableau dashboard

This folder (`tableau/exports/`) contains flat, denormalised CSVs generated by
`src/business_analytics.py`, specifically designed so you can drag them
straight into Tableau with **zero transformation**. This guide walks through
building a 4-sheet dashboard from them in about 15–20 minutes.

Regenerate the exports any time with:
```bash
python -m src.train              # trains/refreshes the model
python -m src.business_analytics # rebuilds all CSVs below
```

## The five data sources

| File | Grain | Use for |
|---|---|---|
| `product_master.csv` | 1 row per product | Scatter plots, filters, product-level tables |
| `category_summary.csv` | 1 row per main × sub category | Category bar/treemap charts |
| `abc_analysis.csv` | 1 row per product, revenue-ranked | Pareto (80/20) chart |
| `pricing_analysis.csv` | 1 row per price band / discount band | Pricing strategy charts |
| `kpi_summary.csv` | 1 row (whole-dataset totals) | KPI scorecards |

**Quick start:** if you only want one data source, use `product_master.csv` —
it has every field you need for products, categories, prices, ratings, and
both actual and predicted sales. The other four are pre-aggregated so you
don't have to build calculated fields for the heavier rollups yourself.

---

## Step 1 — Connect

1. Open Tableau Desktop (or Tableau Public) → **Connect → Text File**.
2. Select `product_master.csv` as your primary source.
3. Add the other four as additional connections in the same workbook
   (Data pane → **Add** → **Text File**). You generally will *not* need to
   join/relate them to `product_master.csv` — treat each as an independent
   data source and put each on its own sheet(s); combine on the dashboard
   canvas instead of at the data layer. This avoids fan-out/join issues
   since the grains are different (product-level vs. category-level).

## Step 2 — KPI scorecard sheet (`kpi_summary.csv`)

1. New sheet → drag `kpi_summary` fields onto **Text** in the Marks card,
   one small worksheet per KPI (Tableau doesn't have a native "big number"
   tile, so the common pattern is one worksheet per metric, sized small,
   arranged in a row on the dashboard):
   - `total_estimated_revenue` → format as currency (₹), Text mark
   - `total_units_sold_est`
   - `avg_rating`
   - `avg_discount_pct`
   - `best_model` + `best_model_r2` (combine into one string via a
     calculated field: `[best_model] + " (R² = " + STR(ROUND([best_model_r2],2)) + ")"`)
2. Set font size large (28–36pt), center-aligned, no gridlines/axes
   (Format → Lines → None). This mimics a KPI "card."

## Step 3 — Revenue by category (`category_summary.csv`)

1. New sheet → Rows: `main_category`. Columns: `SUM(total_estimated_revenue)`.
2. Sort descending by revenue (click the sort icon).
3. Color by `SUM(total_estimated_revenue)` (sequential palette).
4. Try **Marks → Treemap** as an alternative view: drag `main_category` and
   `sub_category` onto **Detail**, `total_estimated_revenue` onto **Size**
   and **Color** — this reveals which sub-categories drive each main
   category's revenue at a glance.
5. Add `avg_rating` and `avg_discount_pct` to **Tooltip** for context on hover.

## Step 4 — Price vs. Sales scatter (`product_master.csv`)

1. New sheet → Columns: `actual_price`. Rows: `total_sales` (or
   `predicted_sales` to see the model's view instead of raw history).
2. Marks → Circle. Color: `main_category`. Size: `estimated_revenue`.
3. Add a trend line: **Analytics pane → Trend Line → Logarithmic** (price↔sales
   relationships are rarely linear — log fits the diminishing-returns shape
   this project's KPI export already flags via `corr_price_vs_sales`).
4. Add a filter on `main_category` and `price_band` so viewers can isolate
   one category at a time.

## Step 5 — ABC / Pareto revenue analysis (`abc_analysis.csv`)

This is the classic "80% of revenue comes from 20% of products" chart.

1. New sheet → Columns: `revenue_rank`. Rows: `estimated_revenue` (bar) —
   set Marks to **Bar**.
2. Add a second measure `cumulative_revenue_pct` as a **Line** on a dual
   axis (Rows shelf → drag `cumulative_revenue_pct` next to the bar
   measure → right-click → **Dual Axis** → **Synchronize Axis**).
3. Color the bars by `abc_tier` (A/B/C) so the three tiers are visually
   distinct.
4. Add a reference line at 80% on the cumulative-% axis
   (right-click axis → **Add Reference Line** → Value 80).
5. This chart answers: *"How many products do we actually need to stock
   deeply vs. long-tail?"* — a genuinely useful inventory-planning view the
   original project never produced.

## Step 6 — Model performance (`model_performance.csv`)

1. New sheet → Columns: `model`. Rows: `R2` (bar), color by model.
2. Duplicate as a second sheet for `MAE` (lower is better — note this in a
   caption) and `train_time_sec` if you want to show the speed/accuracy
   trade-off between Random Forest, Gradient Boosting, and XGBoost.

## Step 7 — Assemble the dashboard

1. **Dashboard → New Dashboard**, size "Automatic" or a fixed 1200×800.
2. Layout top row: the 5 KPI-card sheets from Step 2, side by side.
3. Middle row: Revenue-by-category (Step 3) on the left, Price-vs-Sales
   scatter (Step 4) on the right.
4. Bottom row: ABC/Pareto chart (Step 5) full-width, or side-by-side with
   the model-performance chart (Step 6).
5. Add dashboard-level filters: drag `main_category` from any sheet's
   filter shelf onto the dashboard, then **Apply to Worksheets → All Using
   This Data Source** for the product-level sheets.
6. **Dashboard → Actions** → add a **Filter** action from the category bar
   chart to the scatter plot, so clicking a category bar cross-filters the
   scatter plot.

## Suggested calculated fields

```
// Revenue per unit (margin proxy, since raw cost data isn't in the dataset)
[discount_price]

// Price positioning within category (product_master.csv)
(SUM([actual_price]) - WINDOW_AVG(SUM([actual_price]))) / WINDOW_AVG(SUM([actual_price]))

// Prediction accuracy band (product_master.csv)
IF ABS([prediction_error_pct]) <= 15 THEN "Within 15%"
ELSEIF ABS([prediction_error_pct]) <= 40 THEN "Within 40%"
ELSE "Off by 40%+"
END
```

## A note on the data

`product_master.csv` and friends are built from the bundled **sample**
dataset (see the main `README.md` → "About the data") unless you've swapped
in the real Kaggle dataset and re-run the pipeline. The category/pricing
*patterns* are realistic and designed to produce a genuinely interesting
dashboard, but treat absolute revenue figures as illustrative until you
plug in real data.
